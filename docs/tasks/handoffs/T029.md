## Decisions

- A wrong current password (or 2FA code) is a 400 `validation-failed` naming the field, not a 401:
  the session is valid, and the admin app reads 401 as signed out. 401 is only "no session".
- Turning 2FA off writes `user.two-factor-reset`; a password change and new recovery codes write
  `user.update` with `passwordChanged` / `recoveryCodesRenewed`. `media.delete` was added to
  `AuditActions` (the contract already listed it).
- New recovery codes need 2FA on (400 on `code` otherwise) and answer `Cache-Control: private,
  no-store` with no `Location`.
- `AuditEntryDto` leaves out the `changes` JSON, as the contract's DTO does. Unknown `actorKind`,
  `action`, `targetType` or a bad `since` is a 400 naming the parameter.
- A media delete is a 409 while any post (archived ones too) has it as cover; the foreign key
  catches a race the same way. The file goes after the commit; a missing file is no error.
- The contract's conventions now list `password` as a fixed sub-resource (its own row used it).
- No lockout or rate limit on wrong current passwords: the contract lists no 423 or 429 there.
- The handoff is not in the commit, like the T027 and T028 handoffs.
