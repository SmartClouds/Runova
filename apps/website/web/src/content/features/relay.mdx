## Big jobs, one session at a time

An agent session has a limited context. A large job, such as a new feature across a whole codebase, does not fit in one. Relay splits the job into Markdown task files that each fit one session's context (200K tokens by default), then runs them one after another, each in a fresh session.

## A handoff between every session

Every session writes a handoff file: the purpose of the task, what is done so far, the decisions made, the tests it ran, the workarounds it put in, what was tried and rejected, the open questions, and the next step. The next session reads it first, so it picks up where the last one stopped instead of starting over.

A session ends with one of three outcomes. **Done** moves the task to Done and starts the next one. **Continue** means the session ran out of budget, so a fresh session carries on with the same task. **Blocked** pauses the relay and tells you what the agent needs from you.

## A board that moves by itself

Tasks sit on a board with To do, In progress, Testing, Done and Blocked columns, and the cards move as the relay works. Open a card to read its spec, the handoffs from every session, and each session's agent, model, running time and context use. You can also drag cards yourself.

## Plan the work with AI

You do not have to write the task files by hand. **Split into tasks** has an AI planner size a request into tasks for you, and **Catch up** works out where a project that is already under way stands, so Relay can carry on from there.

## Plan a big job in parts

Not every job is about fitting a context window. **Plan only** breaks a job into parts by what each one delivers, with a full spec per part: goal, context, approach, the files and interfaces it touches, scope, acceptance criteria, a test plan and risks. The planner also writes the plan, its milestones, its risks and the questions only you can answer. Each part can be built now or later, with any agent, from its spec alone.

## Everything in the repo

The plan, its milestones, decisions, workarounds, risks and questions are Markdown files next to the tasks, so git keeps their history and anyone who clones the project has them. Sessions record each decision later work relies on, and each workaround with the package version it waits for. When that version comes out, Runova flags the workaround and turns it into a task with one click. Every session also lands in the task's journal, and **Redo** runs a task again with another agent, from its spec or from what the last attempt learned.

## A task manager, not only a runner

The board has an overview of progress by milestone and what needs you, a list you can sort and filter by priority, size, milestone and label, a roadmap, and the records. Add and edit tasks, tick acceptance criteria and write the plan by hand, or let the agents do it.

## Budgets that hold

With Claude Code, Runova watches the session's real context use and tells it to finish its current step and write the handoff at 80% of its budget, so long tasks still finish without a session running out of room. A task bigger than its budget can keep handing off to fresh sessions with no limit, or run past the budget altogether. Codex and Copilot report their progress through an MCP server, and other agents can run tasks too.
